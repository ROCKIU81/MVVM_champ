КЛАСС: Country (Страна)

Атрибуты:
- id_country: int (Primary Key)
- name: string (NOT NULL, UNIQUE)

Операции:
+ GetChampionships(): List<Championship>
+ GetMatches(): List<Match>

Обоснование операций:
1. GetChampionships() — возвращает все чемпионаты, организованные этой страной
   Почему: Страна может организовать несколько чемпионатов в разные годы.
   Нужна операция для быстрого получения всех чемпионатов конкретной страны.
   Используется при просмотре истории чемпионатов по странам.

2. GetMatches() — возвращает все матчи, в которых участвовала эта страна
   Почему: Страна может участвовать в много матчах (как Team1 или Team2).
   Нужна операция для получения полной истории матчей страны.
   Используется при анализе статистики побед/поражений.

Связи:
- Championship (1:N) — АССОЦИАЦИЯ
  Одна страна организует много чемпионатов.
  Почему ассоциация: Championship может существовать независимо от Country.
  
- Match (1:N) — АССОЦИАЦИЯ (Team1)
  Одна страна может быть первой командой в много матчах.
  Почему ассоциация: Match может существовать независимо.
  
- Match (1:N) — АССОЦИАЦИЯ (Team2)
  Одна страна может быть второй командой в много матчах.
  Почему ассоциация: Match может существовать независимо.

- PlayerSquad (1:N) — АССОЦИАЦИЯ
  Одна страна имеет много игроков в разных матчах.
  Почему ассоциация: PlayerSquad может существовать независимо.

- CoachMatch (1:N) — АССОЦИАЦИЯ
  Одна страна имеет много тренеров в разных матчах.
  Почему ассоциация: CoachMatch может существовать независимо.

КЛАСС: Championship (Чемпионат)

Атрибуты:
- id_championship: int (Primary Key)
- year_played: int (NOT NULL, UNIQUE)
- host_city: string (NOT NULL)
- id_country: int (Foreign Key)

Операции:
+ GetMatches(): List<Match>
+ GetTotalGoals(): int
+ ChampionshipDisplay: string (вычисляемое свойство)

Обоснование операций:
1. GetMatches() — возвращает все матчи этого чемпионата
   Почему: Чемпионат состоит из множества матчей.
   Нужна операция для получения полного расписания чемпионата.
   Используется при просмотре матчей конкретного чемпионата.

2. GetTotalGoals(): int — возвращает общее количество голов в чемпионате
   Почему: Нужна статистика для анализа интенсивности игры.
   Используется при расчете среднего количества голов на матч.
   Помогает сравнивать чемпионаты по результативности.

3. ChampionshipDisplay: string — возвращает читаемое представление
   Почему: Вместо просто года нужно показывать "2022 - Москва".
   Используется в UI для отображения в ComboBox и таблицах.
   Улучшает пользовательский опыт.

Связи:
- Country (1:N) — АССОЦИАЦИЯ
  Один чемпионат организуется одной страной.
  Почему ассоциация: Championship может существовать независимо от Country.
  Обратная связь: Country.Championships

- Match (1:N) — АССОЦИАЦИЯ
  Один чемпионат включает много матчей.
  Почему ассоциация: Match может существовать независимо.
  Обратная связь: Match.Championship

КЛАСС: Match (Матч)

Атрибуты:
- id_match: int (Primary Key)
- championship_id: int (Foreign Key)
- team1_id: int (Foreign Key)
- team2_id: int (Foreign Key)
- team1_score: int (NOT NULL, DEFAULT 0)
- team2_score: int (NOT NULL, DEFAULT 0)

Операции:
+ GetGoals(): List<Goal>
+ GetPlayers(): List<PlayerSquad>
+ GetCoaches(): List<CoachMatch>
+ MatchDisplay: string (вычисляемое свойство)
+ ScoreDisplay: string (вычисляемое свойство)

Обоснование операций:
1. GetGoals() — возвращает все голы этого матча
   Почему: Матч состоит из голов. Нужна операция для получения всех голов.
   Используется при просмотре деталей матча (кто забил, на какой минуте).
   Связь: КОМПОЗИЦИЯ (Match ◆—— Goal)

2. GetPlayers() — возвращает всех игроков, участвовавших в матче
   Почему: Матч включает состав обеих команд.
   Нужна операция для просмотра линейки команд.
   Используется при анализе составов и номеров игроков.
   Связь: АГРЕГАЦИЯ (Match ◇—— PlayerSquad)

3. GetCoaches() — возвращает всех тренеров матча
   Почему: Матч имеет тренеров для каждой команды.
   Нужна операция для просмотра руководства команд.
   Используется при анализе тактики и решений тренеров.
   Связь: АГРЕГАЦИЯ (Match ◇—— CoachMatch)

4. MatchDisplay: string — возвращает читаемое представление
   Почему: Вместо ID нужно показывать "Россия 2:1 Бразилия".
   Используется в UI для отображения в таблицах и ComboBox.
   Улучшает пользовательский опыт.

5. ScoreDisplay: string — возвращает только счет
   Почему: Нужно отображать счет отдельно в некоторых местах UI.
   Используется в таблице матчей для компактного отображения.

Связи:
- Championship (1:N) — АССОЦИАЦИЯ
  Один матч принадлежит одному чемпионату.
  Почему ассоциация: Match может существовать независимо.
  Обратная связь: Championship.Matches

- Country (1:N) — АССОЦИАЦИЯ (Team1)
  Одна страна может быть первой командой в много матчах.
  Почему ассоциация: Match может существовать независимо.
  Обратная связь: Country.Matches

- Country (1:N) — АССОЦИАЦИЯ (Team2)
  Одна страна может быть второй командой в много матчах.
  Почему ассоциация: Match может существовать независимо.
  Обратная связь: Country.Matches

- Goal (1:N) — КОМПОЗИЦИЯ
  Один матч содержит много голов.
  Почему композиция: Goal не может существовать без Match.
  Если матч удалится, все голы удаляются (каскадное удаление).
  Это сильная связь "часть-целое".

- PlayerSquad (1:N) — АГРЕГАЦИЯ
  Один матч включает много игроков в составе.
  Почему агрегация: PlayerSquad логически привязана к Match, но может существовать отдельно.
  Если матч удалится, PlayerSquad теряет смысл, но не удаляется автоматически.

- CoachMatch (1:N) — АГРЕГАЦИЯ
  Один матч имеет много тренеров.
  Почему агрегация: CoachMatch логически привязана к Match, но может существовать отдельно.
  Если матч удалится, CoachMatch теряет смысл, но не удаляется автоматически.

КЛАСС: Person (Человек - Игрок или Тренер)

Атрибуты:
- id_person: int (Primary Key)
- full_name: string (NOT NULL)
- date_of_birth: DateTime (NULL)
- status: string (NOT NULL) — "player" или "coach"

Операции:
+ GetGoals(): List<Goal>
+ GetMatches(): List<Match>

Обоснование операций:
1. GetGoals() — возвращает все голы, забитые этим игроком
   Почему: Нужна статистика забитых голов для каждого игрока.
   Используется при расчете топ-бомбардиров.
   Помогает анализировать результативность игрока.
   Связь: АССОЦИАЦИЯ (Person ↔ Goal)

2. GetMatches() — возвращает все матчи, в которых участвовал этот человек
   Почему: Нужна полная история участия в матчах.
   Используется при просмотре карьеры игрока/тренера.
   Помогает анализировать опыт и статистику.
   Связь: АССОЦИАЦИЯ (Person ↔ PlayerSquad и Person ↔ CoachMatch)

Связи:
- Goal (1:N) — АССОЦИАЦИЯ
  Один игрок может забить много голов.
  Почему ассоциация: Person может существовать без Goal.
  Обратная связь: Goal.Player

- PlayerSquad (1:N) — АССОЦИАЦИЯ
  Один игрок может участвовать в много матчах.
  Почему ассоциация: Person может существовать независимо.
  Обратная связь: PlayerSquad.Player

- CoachMatch (1:N) — АССОЦИАЦИЯ
  Один тренер может руководить много матчей.
  Почему ассоциация: Person может существовать независимо.
  Обратная связь: CoachMatch.Coach

КЛАСС: GoalType (Тип гола)

Атрибуты:
- id_goal_type: int (Primary Key)
- type_name: string (NOT NULL, UNIQUE)
- description: string (NULL)

Операции:
+ GetGoals(): List<Goal>

Обоснование операций:
1. GetGoals() — возвращает все голы этого типа
   Почему: Нужна статистика по типам голов.
   Используется при расчете распределения голов по типам.
   Помогает анализировать тактику игры (сколько голов с игры, пенальти и т.д.).
   Связь: АССОЦИАЦИЯ (GoalType ↔ Goal)

Связи:
- Goal (1:N) — АССОЦИАЦИЯ
  Один тип гола используется в много голах.
  Почему ассоциация: GoalType может существовать независимо.
  Обратная связь: Goal.GoalType

КЛАСС: Goal (Гол)

Атрибуты:
- id_goal: int (Primary Key)
- match_id: int (Foreign Key)
- player_id: int (Foreign Key)
- minute: int (NOT NULL)
- goal_type_id: int (Foreign Key)

Операции:
+ GetPlayerName(): string
+ GetGoalTypeName(): string
+ GetMatchName(): string
+ GoalDisplay: string (вычисляемое свойство)
+ MinuteDisplay: string (вычисляемое свойство)

Обоснование операций:
1. GetPlayerName() — возвращает имя игрока, забившего гол
   Почему: Нужно отображать имя вместо ID.
   Используется в UI для показа информации о голе.

2. GetGoalTypeName() — возвращает название типа гола
   Почему: Нужно отображать тип гола в читаемом виде.
   Используется в UI и статистике.

3. GetMatchName() — возвращает название матча
   Почему: Нужно знать, в каком матче был забит гол.
   Используется в UI для контекста.

4. GoalDisplay: string — полное представление гола
   Почему: Вместо ID нужно показывать "Иван Петров, 15' (с игры)".
   Используется в таблице голов.

5. MinuteDisplay: string — минута в читаемом виде
   Почему: Нужно отображать минуту с форматированием.
   Используется в UI.

Связи:
- Match (1:N) — КОМПОЗИЦИЯ
  Один матч содержит много голов.
  Почему композиция: Goal не может существовать без Match.
  Это сильная связь "часть-целое".
  Если матч удалится, все голы также удаляются (ON DELETE CASCADE).
  Обратная связь: Match.Goals

- Person (1:N) — АССОЦИАЦИЯ
  Один игрок может забить много голов.
  Почему ассоциация: Person может существовать без Goal.
  Обратная связь: Person.Goals

- GoalType (1:N) — АССОЦИАЦИЯ
  Один тип гола используется в много голах.
  Почему ассоциация: GoalType может существовать независимо.
  Обратная связь: GoalType.Goals

+ TeamName: string (вычисляемое свойство)

   Используется в таблице состава.

2. PlayerName — имя игрока
   Почему: Нужно отображать имя вместо ID.
   Используется в UI.

3. TeamName — название команды
   Почему: Нужно знать, за какую команду играет игрок в этом матче.
   Используется в UI.

4. MatchName — название матча
   Почему: Нужно знать, в каком матче участвовал игрок.
   Используется в UI.

Связи:
- Match (1:N) — АГРЕГАЦИЯ
  Один матч включает много игроков в составе.
  Почему агрегация: PlayerSquad логически привязана к Match, но может существовать отдельно.
  Если матч удалится, PlayerSquad теряет смысл, но не удаляется автоматически.
  Обратная связь: Match.Players

- Person (1:N) — АССОЦИАЦИЯ
  Один игрок может участвовать в много матчах.
  Почему ассоциация: Person может существовать независимо.
  Обратная связь: Person.PlayerSquads

- Country (1:N) — АССОЦИАЦИЯ
  Одна команда имеет много игроков в разных матчах.
  Почему ассоциация: Country может существовать независимо.
  Обратная связь: Country.PlayerSquads

КЛАСС: CoachMatch (Тренер матча)

Атрибуты:
- id_record: int (Primary Key)
- match_id: int (Foreign Key)
- coach_id: int (Foreign Key)
- team_id: int (Foreign Key)

Операции:
+ GetCoachDisplay(): string
+ CoachName: string (вычисляемое свойство)
+ TeamName: string (вычисляемое свойство)
+ MatchName: string (вычисляемое свойство)

Обоснование операций:
1. GetCoachDisplay() — полное представление тренера матча
   Почему: Нужно показывать "Станислав Черчесов (Россия)".
   Используется в таблице тренеров.

2. CoachName — имя тренера
   Почему: Нужно отображать имя вместо ID.
   Используется в UI.

3. TeamName — название команды
   Почему: Нужно знать, какую команду тренировал тренер в этом матче.
   Используется в UI.

4. MatchName — название матча
   Почему: Нужно знать, в каком матче тренировал тренер.
   Используется в UI.

Связи:
- Match (1:N) — АГРЕГАЦИЯ
  Один матч имеет много тренеров (по одному на каждую команду).
  Почему агрегация: CoachMatch логически привязана к Match, но может существовать отдельно.
  Если матч удалится, CoachMatch теряет смысл, но не удаляется автоматически.
  Обратная связь: Match.Coaches

- Person (1:N) — АССОЦИАЦИЯ
  Один тренер может руководить много матчей.
  Почему ассоциация: Person может существовать независимо.
  Обратная связь: Person.CoachMatches

- Country (1:N) — АССОЦИАЦИЯ
  Одна команда имеет много тренеров в разных матчах.
  Почему ассоциация: Country может существовать независимо.
  Обратная связь: Country.CoachMatches
