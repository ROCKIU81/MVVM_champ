1. MVVM (Model-View-ViewModel) ПАТТЕРН

Описание:
Основной архитектурный паттерн приложения. Разделяет приложение на три слоя:
- View (представление) — XAML файлы в папке view/
- ViewModel — классы в папке viewmodels/
- Model — классы в папке models/

Реализация:
- View слой: MainWindow.xaml, MainWindow.xaml.cs
- ViewModel слой: ViewModelBase, CountryViewModel, MatchViewModel и т.д.
- Model слой: Country, Championship, Match, Person, Goal и т.д.
- Binding между View и ViewModel через DataContext

Файлы:
- viewmodels/ViewModelBase.cs
- viewmodels/CountryViewModel.cs
- viewmodels/MatchViewModel.cs
- view/MainWindow.xaml

2. COMMAND ПАТТЕРН

Описание:
Инкапсулирует запрос как объект, позволяя параметризовать клиентов с 
различными запросами, ставить запросы в очередь, регистрировать запросы 
и поддерживать отмену операций.

Реализация:
- RelayCommand класс реализует ICommand интерфейс
- AsyncRelayCommand для асинхронных операций
- Каждый ViewModel содержит команды (LoadCommand, SaveCommand, DeleteCommand)

Файлы:
- viewmodels/RelayCommand.cs (RelayCommand и AsyncRelayCommand)
- viewmodels/CountryViewModel.cs (использует RelayCommand)
- viewmodels/MatchViewModel.cs (использует RelayCommand)

Пример использования:
public RelayCommand LoadCommand { get; }
public RelayCommand SaveCommand { get; }
public RelayCommand DeleteCommand { get; }

3. REPOSITORY ПАТТЕРН

Описание:
Абстрагирует логику доступа к данным и предоставляет коллекцию-подобный 
интерфейс для доступа к объектам домена.

Реализация:
- Интерфейсы репозиториев: ICountryRepository, IMatchRepository и т.д.
- Реализации репозиториев: CountryRepository, MatchRepository и т.д.
- Каждый репозиторий работает с одной сущностью
- CRUD операции: GetAllAsync, GetByIdAsync, AddAsync, UpdateAsync, DeleteAsync

Файлы:
- services/CountryRepository.cs
- services/MatchRepository.cs
- services/PersonRepository.cs
- services/GoalRepository.cs
- services/ChampionshipRepository.cs
- services/GoalTypeRepository.cs
- services/PlayerSquadRepository.cs
- services/CoachMatchRepository.cs

Интерфейсы:
- ICountryRepository
- IMatchRepository
- IPersonRepository
- IGoalRepository
- IGoalTypeRepository
- IPlayerSquadRepository
- ICoachMatchRepository

4. DEPENDENCY INJECTION (DI) ПАТТЕРН

Описание:
Предоставляет зависимости объекту вместо того, чтобы объект сам их создавал.
Повышает гибкость, тестируемость и слабую связанность кода.

Реализация:
- CrudService получает репозитории через конструктор
- StatisticsService получает репозитории через конструктор
- ViewModel получают сервисы через конструктор
- Использование интерфейсов для инъекции

Файлы:
- services/CrudService.cs (инъекция 8 репозиториев)
- services/StatisticsService.cs (инъекция 4 репозиториев)
- viewmodels/CountryViewModel.cs (инъекция CrudService)
- viewmodels/MatchViewModel.cs (инъекция CrudService)

Пример:
public CrudService(
    ICountryRepository countryRepository,
    IChampionshipRepository championshipRepository,
    IMatchRepository matchRepository,
    IPersonRepository personRepository,
    IGoalRepository goalRepository,
    IGoalTypeRepository goalTypeRepository,
    IPlayerSquadRepository playerSquadRepository,
    ICoachMatchRepository coachMatchRepository)

5. SERVICE LAYER ПАТТЕРН

Описание:
Инкапсулирует бизнес-логику в отдельном слое сервисов, отделяя её от 
представления и доступа к данным.

Реализация:
- CrudService — обработка CRUD операций
- StatisticsService — расчёт статистики
- Сервисы используют репозитории для доступа к данным
- ViewModel вызывают методы сервисов

Файлы:
- services/CrudService.cs
- services/StatisticsService.cs

Методы CrudService:
- SaveCountryAsync(Country)
- DeleteCountryAsync(int)
- SaveChampionshipAsync(Championship)
- SaveMatchAsync(Match)
- SaveGoalAsync(Goal)
- SavePersonAsync(Person)
- SavePlayerSquadAsync(PlayerSquad)
- SaveCoachMatchAsync(CoachMatch)

Методы StatisticsService:
- GetTopScorersAsync(int)
- GetGoalsByTypeAsync()
- GetMatchesByChampionshipAsync()
- GetTeamStatisticsAsync()

6. OBSERVABLE COLLECTION ПАТТЕРН

Описание:
Предоставляет коллекцию, которая автоматически уведомляет UI об изменениях.

Реализация:
- ObservableCollection<T> используется во всех ViewModel
- Автоматическое обновление UI при добавлении/удалении элементов
- Двусторонний binding между View и ViewModel

Файлы:
- viewmodels/CountryViewModel.cs
- viewmodels/MatchViewModel.cs
- viewmodels/StatisticsViewModel.cs

Пример:
public ObservableCollection<Country> Countries { get; set; }
public ObservableCollection<Match> Matches { get; set; }
public ObservableCollection<TopScorerStatistic> TopScorers { get; set; }

7. PROPERTY CHANGED NOTIFICATION ПАТТЕРН

Описание:
Уведомляет UI об изменении свойств через INotifyPropertyChanged интерфейс.

Реализация:
- ViewModelBase реализует INotifyPropertyChanged
- Все ViewModel наследуют ViewModelBase
- OnPropertyChanged вызывается при изменении свойств
- Использует CallerMemberName для автоматического получения имени свойства

Файлы:
- viewmodels/ViewModelBase.cs

Код:
public class ViewModelBase : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;
    
    public void OnPropertyChanged([CallerMemberName] string prop = "")
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(prop));
    }
}

8. ASYNC/AWAIT ПАТТЕРН

Описание:
Асинхронное выполнение операций без блокирования UI потока.

Реализация:
- Все методы репозиториев асинхронные (GetAllAsync, AddAsync и т.д.)
- Все методы сервисов асинхронные
- AsyncRelayCommand для асинхронных команд
- Использование Task и Task<T>

Файлы:
- services/CrudService.cs (async методы)
- services/StatisticsService.cs (async методы)
- viewmodels/RelayCommand.cs (AsyncRelayCommand)

Пример:
public async Task SaveCountryAsync(Country country)
{
    if (country.Id == 0)
        await _countryRepository.AddAsync(country);
    else
        await _countryRepository.UpdateAsync(country);
}

9. ENTITY FRAMEWORK CORE ПАТТЕРН

Описание:
ORM (Object-Relational Mapping) для работы с базой данных через объекты.

Реализация:
- Модели (Country, Match, Person и т.д.) как Entity классы
- DbContext для работы с БД
- Навигационные свойства для связей между сущностями
- LINQ запросы для работы с данными

Файлы:
- models/Country.cs
- models/Match.cs
- models/Person.cs
- models/Goal.cs
- services/PostgresRep.cs (DbContext)

10. FACTORY ПАТТЕРН (косвенно)

Описание:
Создание объектов через фабрики вместо прямого использования new.

Реализация:
- Dependency Injection контейнер создаёт объекты
- Сервисы создаются через DI контейнер
- Репозитории создаются через DI контейнер

ЗАКЛЮЧЕНИЕ

Ваш проект использует 10 основных паттернов проектирования:

1. MVVM — основная архитектура приложения
2. Command — для обработки команд в UI
3. Repository — для абстракции доступа к данным
4. Dependency Injection — для управления зависимостями
5. Service Layer — для инкапсуляции бизнес-логики
6. Observable Collection — для автоматического обновления UI
7. Property Changed Notification — для уведомления об изменениях
8. Async/Await — для асинхронных операций
9. Entity Framework Core — для работы с БД
10. Factory (через DI) — для создания объектов

Это хорошо спроектированное приложение, которое следует лучшим практикам 
разработки на C# и WPF.
